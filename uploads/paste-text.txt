Before adding any new features, perform a complete production-readiness audit of the current DishBar application.

The goal is to prepare DishBar for a small private pilot with one chef and a limited number of customers in Ontario.

Do not claim that any feature is working unless you have tested and verified it.

Complete the following tasks in order:

Audit the current application

Review the frontend, backend, database, authentication, payments, order processing, chef portal, customer portal and admin portal.

Create a checklist showing:

Fully working features
Partially implemented features
Mock or placeholder features
Features with hardcoded data
Features that are only visual and are not connected to the backend
Security or privacy risks
Missing environment variables
Missing third-party integrations
Errors that would prevent real customers from ordering
Verify authentication

Confirm that customer, chef and administrator accounts have separate permissions.

Test:

Customer registration and login
Chef registration and login
Administrator login
Password or phone verification
Logout
Session persistence
Protected routes
Prevention of customers accessing chef or administrator pages
Prevention of chefs accessing administrator functions

If SMS OTP is not connected to a real provider, clearly identify it as incomplete. Do not simulate successful OTP authentication in production.

Verify Stripe payments

Confirm whether Stripe is currently operating in test mode or live mode.

Verify:

Stripe keys are stored securely
No secret key is exposed in frontend code
Checkout sessions are created by the backend
Payment amount is calculated on the backend
Delivery fees, taxes, discounts, tips and totals cannot be manipulated from the browser
Payment success is confirmed through Stripe webhooks
Failed or abandoned payments do not create paid orders
Refunds work
Duplicate charges are prevented
Stripe Connect chef accounts are genuinely connected
Commission calculations are correct
Payouts are disabled or manual during the pilot unless fully verified

Display a clear warning in the admin portal if Stripe is not fully configured.

Replace fake distance calculations

The current delivery fee must not be based only on matching the customer’s typed address to a list of Ontario cities.

Implement proper address validation and geocoding.

Requirements:

Store each chef’s complete pickup address securely
Ask customers for a complete delivery address
Convert both addresses to coordinates through a reliable maps or geocoding service
Calculate the actual route distance when possible
Prevent checkout when the address cannot be verified
Allow the administrator to configure:
Base delivery fee
Included distance
Per-kilometre fee
Maximum delivery distance
Maximum delivery fee
Free-pickup option
Show the customer the distance, delivery fee and estimated delivery area before payment
Do not publicly display the chef’s private home address

For the initial pilot, create a simpler backup option allowing the administrator to define delivery zones by postal-code prefix and set a fixed fee for each zone.

Create a pilot mode

Add a configurable PILOT_MODE setting.

When pilot mode is active:

Only approved chefs appear publicly
Only selected postal-code areas can order
The administrator can set opening days and ordering hours
The administrator can set a daily order limit
The administrator can pause all ordering immediately
Customers see a message explaining that DishBar is currently operating as a limited pilot
Chef payouts remain manual
New chef applications can be collected but cannot automatically go live

Platform open or closed

Terms and policy links
Complete the order workflow

Test the full process:

Customer selects meals → inventory is checked → delivery or pickup is selected → address is validated → fees and taxes are calculated → payment is completed → order is created → chef receives notification → chef accepts or rejects the order → customer receives status updates → order is prepared → order is completed → refund or dispute can be handled by the administrator.

Inventory must be reduced only after successful payment or order confirmation.

Prevent:

Ordering unavailable meals
Ordering more than available quantity
Ordering outside the chef’s schedule
Ordering outside the delivery area
Ordering after the cutoff time
Two customers purchasing the final available item simultaneously

Display a clear notice that customers with severe allergies should contact the chef before ordering and that DishBar cannot guarantee an allergen-free environment unless specifically confirmed.
